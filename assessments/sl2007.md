## 7. Controls (axis: 100.0)

Cabinet: standard NAOMI panel, **8-way joystick + 3 buttons** — Shoot / Bomb / Full-Auto (arcadeitalia machine DB). `controls.device_class = stick`. MAME input ports: `naomi` (`INPUT_PORTS_START(naomi)` at naomi.cpp @59e7c0b line 1506 — the generic Naomi port framework provisions up to 6 buttons/player, but the actual cabinet only wires 3; `sl2007`'s `GAME()` row at line 11115 declares `input_ports=naomi`). No gun/analog-peripheral port is present for this title in either source — confirming the QUEUE.md "Light-gun" label is wrong (§2/§9).
Proposed DC mapping: d-pad (or analog stick) for the 8-way joystick + 3 face buttons (A=Shoot, B=Bomb, C=Full-Auto), 1:1 — the same "the Dreamcast D-pad is up to the job" shape as `trizeal`'s official DC port (`assessments/trizeal.md` §7), from the same developer.
Sources: MAME src/mame/sega/naomi.cpp @59e7c0b `INPUT_PORTS_START(naomi)` (line 1506), `ROM_START(sl2007)` (line 6674), `GAME()` row (line 11115);
[arcadeitalia MAME machine DB](http://adb.arcadeitalia.net/dettaglio_mame.php?game_name=sl2007) ("8-Way Joystick", 3 buttons Shoot/Bomb/Full-Auto, up to 2 players);
[Wikipedia, "Shooting Love, 200X"](https://en.wikipedia.org/wiki/Shooting_Love,_200X) (contents, lineage, X360 port date — corroborates the cabinet is a conventional shmup stick setup, not a peripheral-driven cabinet).

## 8. Score computation

final = memory^.40 · streaming^.20 · guts^.20 · controls^.10 · similarity^.10
      = 100.0^.40 · 90.7^.20 · 85.0^.20 · 100.0^.10 · 40.0^.10 = **86.6 (S)**
Similarity inputs: developer no, SDK overlap partial, loader match no → 40.0. Both sub-flags are mechanical
reference-list artifacts, not real dissimilarity signals: the calibration reference
(`assessments/reference/similarity-reference.json`) is Altron/Taito **GD-ROM** only, so (a) no third-party
developer (Triangle Service included) can ever match `developer_match`, and (b) no **cart** title (`sl2007`
is `naomim4`) can ever match `cart_loader_match` regardless of engine similarity, since the reference's
`format` field is literally `"GD-ROM"` — same caveat noted for `senko`/`senkosp`/`illvelo`/`sfz3ugd`.

## 9. Risks & notes

- **Genre-label correction (carried through from QUEUE.md/GAME_FORMATS.md, both left unchanged per campaign
  precedent — `sstrkfgt`, `mazan`):** this family is filed as "Light-gun" in the queue tables. It is not — it
  is a stick-controlled shmup mini-compilation, confirmed independently by MAME's input ports and the
  arcadeitalia control-panel DB (§2/§7). The controls research in this doc was driven by that verified
  cabinet data, not the queue label.
- **Two informational watermark matches worth recording for the campaign, not the score:** main's address
  peak (32,505,920) is an exact hit on the shared `0x1F00040` boot-time structure (kb §6 item 3) — the sixth
  campaign instance and the second on an M4 cart; ARAM's address peak (2,097,136) matches `trizeal`/`karous`/
  `illvelo`'s identical value — the fourth instance, and the second Triangle Service title after `trizeal`
  itself. Both are informational-only under v9's content-volume keying (§4); neither moves this title's score.
- **Primary-source content confirmation**: the carved binary's own strings (§2, §6) — a literal Exzeal stage
  title `FORTRESS "TRIZEAL"` and XII Stag asset paths — verify the developer-lineage claim directly from this
  ROM dump, not solely from external research.
- **DC lineage**: same developer as `trizeal` (72.5 A, shipped DC 2005) — that title's official port is direct
  evidence this developer's engine/asset pipeline already crossed to Dreamcast once; `sl2007`'s own DC port was
  planned and cancelled (§2), not blocked technically.
- Similarity axis capped by reference-list format/developer mismatch, not a real dissimilarity signal — see §8.
- Rendering must be verified on real DC hardware per working-style rule — this is an emulator-only (Flycast)
  measurement.
